comment ça marche

Ce que fait Strix

  • Il attaque pour de vrai. Ses agents testent ton appli comme un attaquant : un client qui voit les données d'un autre, une connexion qu'on contourne, des injections SQL, du XSS, une logique de paiement qu'on détourne, une configuration exposée.
  • Il prouve ce qu'il trouve. Le projet valide chaque faille par une preuve d'exploitation qui marche, pour éviter les fausses alertes des scanners classiques.
  • Il te rend le rapport. Les résultats sont rangés dans strix_runs/, et strix view les ouvre dans un tableau de bord sur ta machine.
  • Il peut lire ton code ou viser ton site en ligne. Un dossier sur ton ordi, un dépôt GitHub ou une adresse web : il prend les trois.
  • Tout tourne chez toi, dans Docker. Licence Apache 2.0. Une version en ligne sans installation existe aussi : app.strix.ai.

les pièges à éviter
  • Teste seulement ce qui t'appartient. Strix attaque vraiment. Le lancer sur l'appli de quelqu'un d'autre sans son accord écrit, c'est illégal.
  • Commence en mode rapide, avec un plafond. Par défaut, Strix fait un test approfondi qui consomme beaucoup d'appels à l'IA. --scan-mode quick et --max-budget gardent la facture sous contrôle.
  • Commite ton code avant. Quand tu vises un dossier sur ton ordi, Strix peut y écrire : fais un commit avant de lancer.
  • Vise une version de test si tu en as une. Un test d'intrusion sur l'appli en ligne peut créer des comptes ou des données, mieux vaut que ce ne soit pas chez tes vrais clients.

Tu préfères le faire à la main ?
Suis ces étapes.

étape 1 · prérequis5 min

Deux choses : Docker qui tourne, et une clé API d'un fournisseur d'IA (Anthropic, OpenAI, Google ou OpenRouter). Vérifie Docker :

docker info

Pas de Docker ? Installe Docker Desktop sur docker.com et lance le. Ton abonnement Claude ne suffit pas ici : il faut une clé API, facturée à l'usage.

étape 2 · installer1 cmd
curl -sSL https://strix.ai/install | bash

Ou avec pipx

pipx install strix-agent

Sur Windows, lance ces commandes dans WSL (le terminal Linux de Windows), avec Docker Desktop ouvert.

étape 3 · ta clé1 min

Choisis le modèle et colle ta clé. Exemple avec Claude :

export STRIX_LLM="anthropic/claude-sonnet-4-6"
export LLM_API_KEY="ta-cle-api"

Strix garde ta configuration dans ~/.strix/cli-config.json, tu n'as pas à la retaper à chaque fois.

étape 4 · lancer le test1 cmd

Sur le code de ton appli

strix --target ./mon-appli --scan-mode quick --max-budget 5

Sur ton appli en ligne

strix --target https://ton-appli.com --scan-mode quick --max-budget 5

Avec un compte de test, pour tester ce qu'il y a derrière la connexion

strix --target https://ton-appli.com --instruction "Connecte toi avec le compte de test : email / mot de passe"

--max-budget plafonne ce que le test dépense en appels à l'IA, en dollars. Le premier lancement télécharge l'environnement Docker de Strix, c'est normal qu'il prenne un peu de temps.

étape 5 · lire le rapport1 cmd

Les résultats sont dans strix_runs/. Pour les voir dans un tableau de bord :

strix view

Le plus simple ensuite : donne le rapport à Claude et demande lui de corriger les failles une par une, de la plus grave à la moins grave.
